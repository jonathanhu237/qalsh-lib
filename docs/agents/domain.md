# Domain Docs

This repository uses a single domain context.

- Read root `CONTEXT.md` before exploring domain behavior.
- Read relevant decisions under `docs/adr/`.
- If these documents are absent, proceed silently.
- Use the glossary's canonical terminology.
- Surface conflicts with existing ADRs instead of silently
  overriding them.
- Create domain documents lazily through domain modeling;
  do not create empty placeholders.
